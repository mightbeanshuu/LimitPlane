Attach

Attach to any site in a few steps

Run the proxy in front of anything (Python, PHP, Rails, even a static site; it never knows the layer is there), or import the middleware if you're on Node.

1

One command. Protected.

No install, no clone, no config. Point it at your site and send traffic to port 3000. Every visitor gets 60 requests/minute out of the box.

npx github:mightbeanshuu/LimitPlane --upstream http://localhost:8080
2

Price your AI routes with flags

Mark expensive endpoints heavy (5 tokens each) and tune the per-visitor budget.

npx github:mightbeanshuu/LimitPlane --upstream http://localhost:8080 \
  --rpm 120 --heavy /api/ai-scan,/api/generate
3

Go multi-tenant when you're ready

A config file adds tiers, API keys, monthly quotas, and per-customer budgets. Blocked requests get a clean 429 and never reach your servers.

cp limitplane.config.example.json limitplane.config.json
node bin/limitplane.js --config limitplane.config.json
1

Install straight from GitHub

npm install github:mightbeanshuu/LimitPlane
2

Create the layer with your policy

import { createLimitPlane } from "limitplane";

const lp = createLimitPlane({ policy: {
  tiers:  { free: { capacity: 10, refillPerSecond: 1, monthlyQuota: 1000 },
            pro:  { capacity: 50, refillPerSecond: 5, monthlyQuota: 50000 } },
  routes: { "/v1/scan": { costClass: "heavy" },
            "*":        { costClass: "light" } },
  tenants:{ "customer-key": { tenantId: "acme", tier: "pro" } },
}});
3

Mount it and you're done

app.use(lp.middleware);            // Express / connect

// or on plain node:http:
const d = await lp.middleware(req, res);
if (!d.allowed) return;            // 429 already sent
How it works

Two meters per request, one automated billing loop

Every request answers two questions in order: does your plan have units left this month, and are you going too fast right now? Every verdict lands in an audit log with the facts.

            ┌─────────────────────────────────────────────────┐
 request ──▶│                LIMITPLANE LAYER                 │──▶ your site
            │  1 WHO?     x-api-key → tenant + tier           │
            │  2 WHAT?    route → light 1 · standard 2 · heavy 5 │
            │  3 PLAN     monthly meter, resets on the 1st    │
            │  4 BURST    token bucket per tenant:tier:route  │
            │  5 VERDICT  pass, or 429 that says WHY:         │
            │             "slow down" vs "upgrade your plan"  │
            └─────────────────────────────────────────────────┘
 THE BILLING AUTOMATION (no human in the loop)

 customer clicks upgrade ──▶ Stripe Checkout (hosted; we never see cards)
                                   │ payment succeeds
                                   ▼
             Stripe signs + POSTs /v1/billing/webhook
                                   │ HMAC signature verified
                                   ▼
              tenant's tier flips in the TenantStore
                                   ▼
     the very next request is limited under the new plan
     cancellations & failed payments flow back the same way → auto-downgrade

Under the hood

Small, honest engineering

A learning-grade codebase you can actually read: every file is commented like a lesson.

8 limiter algorithms

Fixed window, sliding log and counter, token bucket, leaky bucket, monthly quota, plus two distributed Redis variants. All from scratch, all tested.

Billing you can read

Stripe integration in one file with zero SDKs: raw HTTPS, form encoding, and one HMAC for webhook signatures. Swap in the official SDK later; nothing structural changes.

Two-meter design

The monthly meter protects the customer's wallet; the burst bucket protects your servers. A blocked plan never drains burst tokens.

Tenant isolation

Buckets are keyed tenant:tier:route. One customer burning their budget mathematically cannot touch anyone else's.

Autopilot with an AI voice

Quota alerts at 80%, upgrade nudges at the cap, and auto-cooldown bans for retry-storms. Each action ships with an LLM-written incident note based on real audit facts, falling back to templates when no key is set.

Deterministic tests

Injectable clocks everywhere, so tests fast-forward to next month instead of sleeping. 32 unit tests cover allow, block, reset, isolation, billing, and the autopilot.

Fails loudly

Unknown tiers, plans, or cost classes throw at config time. Unsigned webhooks are rejected before a byte is trusted.
